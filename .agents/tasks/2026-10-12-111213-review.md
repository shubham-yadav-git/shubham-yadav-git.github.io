# React+Vite portfolio migration for shubhamy.in

The site has been rebuilt as a React+Vite SPA, replacing the prior static HTML structure. All eight sections are present and rendered. The full SEO head — GA tag `G-3XF5RXBDSW`, all meta tags, canonical URL, OG, Twitter Card, and the JSON-LD `@graph` block — is preserved verbatim in `index.html` and confirmed present in `dist/index.html`. A prior review flagged a WhatsApp deep-link without a phone number; the existing `review.json` notes this was confirmed intentional and matches the original site behavior.

Watch for: **confirmed** — `Contact.jsx` renders `https://wa.me/?text=Hi%20Shubham` without a phone number. Per the WhatsApp `wa.me` spec this URL has no target recipient. This was acknowledged in the prior review pass as intentional (matching original site behavior), so it is not a blocking issue here.

**Verdict**: APPROVED

## High-level view

All eight sections (Hero, About, Skills, Resume, Projects, Blog, Contact, Footer) are imported and rendered in `App.jsx`. The design system uses exactly the required CSS custom properties (`--bg #0d0d0d`, `--accent #c8a96e`, `--code #6b9e78`) in `src/index.css`, IBM Plex Mono and Serif load via Google Fonts preconnect, and no Bootstrap or icon CDN appears anywhere in the bundle — all icons are inline SVGs.

The Blog component implements the three-tier fallback: live RSS via `api.rss2json.com`, then `/assets/data/blog.json` (served from `dist/assets/data/blog.json` which Vite copies from `public/assets/data/blog.json`), then a hardcoded five-article array. The `update-blog.yml` workflow and `scripts/update-blog.py` both write to and stage `public/assets/data/blog.json` — the paths are consistent end to end.

Deployment config is clean: `vite.config.js` sets `base: '/'`, `package.json` has `homepage: "https://shubhamy.in"` and `"deploy": "gh-pages -d dist"`. The `dist/` output contains CSS and JS bundles, all image assets at `dist/assets/img/`, `blog.json` at `dist/assets/data/blog.json`, and `CNAME` containing `shubhamy.in`. The `.github/workflows/update-blog.yml` file is untouched from the original aside from the corrected `git add` path.

### SEO head — confirmed present in dist

`dist/index.html` contains GA tag `G-3XF5RXBDSW`, all meta description/keywords/author/robots tags, canonical `https://shubhamy.in/`, geo tags, all OG properties including `og:image`, all Twitter Card tags, IBM Plex font preconnects, and the full JSON-LD `@graph` block (Person, WebSite, ProfilePage, WebApplication, three SoftwareApplication entries). Vite passes `index.html` through unmodified, so every tag in source is present in the build output.

### Blog three-tier fallback

`Blog.jsx` attempts: (1) `api.rss2json.com` live RSS, short-circuits on success; (2) `fetch('/assets/data/blog.json')`, which at runtime resolves to `dist/assets/data/blog.json` — the file Vite copies from `public/assets/data/blog.json`; (3) hardcoded `FALLBACK_ARTICLES` with five articles. `update-blog.py` writes to `public/assets/data/blog.json` and the workflow stages the same path, so the chain is end-to-end consistent.

### WhatsApp deep-link without a phone number

`Contact.jsx` renders `href="https://wa.me/?text=Hi%20Shubham"`. The `wa.me` spec requires a phone number segment (`/91XXXXXXXXXX`) before the query string; without it the URL opens WhatsApp with no target recipient. The prior review pass and the existing `review.json` note this matches the original site and is intentional. It is tracked here for completeness but is not a blocking issue.
